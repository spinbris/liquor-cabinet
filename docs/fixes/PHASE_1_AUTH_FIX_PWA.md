## Task 1: Fix Cross-Device User ID Mismatch

### Problem
NextAuth v5 with JWT strategy (no database adapter) generates a random UUID for `user.id` on each fresh sign-in. Same Google account gets different user_ids on different devices:
- PC: `aae7d4d6-b45c-4342-a03f-5ee17ab6d09f` → 52 bottles (PRIMARY)
- Phone: `6df56e85-36db-4090-aeef-5010ab5ac25d` → 1 bottle
- Unknown: `a5939ba8-b410-4509-9dc1-d8753262693b` → 5 bottles

### Root Cause
In `lib/auth.ts`, the JWT callback uses `user.id` which is a random UUID generated by NextAuth when there's no database adapter. It should use Google's stable `sub` identifier instead.

### Fix Part A: Update auth.ts to use Google's stable account ID

Replace `lib/auth.ts` with:

```typescript
import NextAuth from "next-auth";
import Google from "next-auth/providers/google";

export const { handlers, signIn, signOut, auth } = NextAuth({
  providers: [
    Google({
      clientId: process.env.AUTH_GOOGLE_ID!,
      clientSecret: process.env.AUTH_GOOGLE_SECRET!,
    }),
  ],
  callbacks: {
    async jwt({ token, account, profile }) {
      // On first sign-in, use Google's stable subject identifier
      // This is the same for the same Google account regardless of device
      if (account && profile) {
        token.sub = profile.sub;
      }
      return token;
    },
    async session({ session, token }) {
      if (token.sub) {
        session.user.id = token.sub;
      }
      return session;
    },
  },
  pages: {
    signIn: "/auth",
  },
  trustHost: true,
});
```

Key change: `profile.sub` is Google's stable unique identifier for the account. It's the same value regardless of which device or browser signs in.

### Fix Part B: Data Migration

After deploying the auth fix, the existing data needs to be consolidated. The Google `profile.sub` will be a numeric string (like `"117234567890123456789"`), NOT a UUID. So we need to:

1. First, deploy the auth fix
2. Have the user sign in on any device to get the new stable Google `sub` 
3. Run a one-time migration to update all old user_ids to the new Google sub

Create a migration API endpoint at `app/api/migrate-user/route.ts`:

```typescript
import { NextResponse } from "next/server";
import { auth } from "@/lib/auth";
import { sql } from "@/lib/neon";

// ONE-TIME migration endpoint - delete after use
export async function POST() {
  const session = await auth();
  if (!session?.user?.email) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  // Only allow Steve to run this
  if (session.user.email !== "stephen.parton@gmail.com") {
    return NextResponse.json({ error: "Forbidden" }, { status: 403 });
  }

  const newUserId = session.user.id;

  // The old UUIDs to consolidate
  const oldUserIds = [
    "aae7d4d6-b45c-4342-a03f-5ee17ab6d09f",
    "6df56e85-36db-4090-aeef-5010ab5ac25d",
    "a5939ba8-b410-4509-9dc1-d8753262693b",
  ];

  try {
    let bottlesUpdated = 0;
    let eventsUpdated = 0;

    for (const oldId of oldUserIds) {
      const bottleResult = await sql`
        UPDATE bottles SET user_id = ${newUserId} WHERE user_id = ${oldId}
      `;
      const eventResult = await sql`
        UPDATE inventory_events SET user_id = ${newUserId} WHERE user_id = ${oldId}
      `;
      // neon returns array of affected rows
      bottlesUpdated += Array.isArray(bottleResult) ? bottleResult.length : 0;
      eventsUpdated += Array.isArray(eventResult) ? eventResult.length : 0;
    }

    // Verify
    const verification = await sql`
      SELECT COUNT(*) as count FROM bottles WHERE user_id = ${newUserId}
    `;

    return NextResponse.json({
      success: true,
      newUserId,
      bottlesUpdated,
      eventsUpdated,
      totalBottlesNow: parseInt(verification[0].count),
    });
  } catch (error) {
    console.error("Migration error:", error);
    return NextResponse.json(
      { error: "Migration failed", details: String(error) },
      { status: 500 }
    );
  }
}
```

### Fix Part C: Change user_id column type (if needed)

The current `user_id` column is likely UUID type. Google's `sub` is a numeric string (e.g., `"117234567890123456789"`). We may need to alter the column type to TEXT. Check first:

If the column is UUID type, we need to alter it BEFORE the migration:
```sql
ALTER TABLE bottles ALTER COLUMN user_id TYPE TEXT;
ALTER TABLE inventory_events ALTER COLUMN user_id TYPE TEXT;
```

Create `app/api/migrate-schema/route.ts` for this:

```typescript
import { NextResponse } from "next/server";
import { auth } from "@/lib/auth";
import { sql } from "@/lib/neon";

// ONE-TIME schema migration - delete after use
export async function POST() {
  const session = await auth();
  if (!session?.user?.email || session.user.email !== "stephen.parton@gmail.com") {
    return NextResponse.json({ error: "Forbidden" }, { status: 403 });
  }

  try {
    // Check current column type
    const colInfo = await sql`
      SELECT column_name, data_type 
      FROM information_schema.columns 
      WHERE table_name = 'bottles' AND column_name = 'user_id'
    `;

    const currentType = colInfo[0]?.data_type;

    if (currentType === 'uuid') {
      // Need to convert to text
      await sql`ALTER TABLE bottles ALTER COLUMN user_id TYPE TEXT`;
      await sql`ALTER TABLE inventory_events ALTER COLUMN user_id TYPE TEXT`;
      return NextResponse.json({ 
        success: true, 
        message: "Columns converted from UUID to TEXT",
        previousType: currentType 
      });
    }

    return NextResponse.json({ 
      success: true, 
      message: "No change needed",
      currentType 
    });
  } catch (error) {
    return NextResponse.json({ error: String(error) }, { status: 500 });
  }
}
```

### 2D: Create Service Worker

Create `public/sw.js`:

```javascript
const CACHE_NAME = 'liquor-cabinet-v1';

// Assets to cache on install
const PRECACHE_ASSETS = [
  '/',
  '/inventory',
  '/add',
  '/recipes',
];

// Install event - cache app shell
self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(CACHE_NAME).then((cache) => {
      return cache.addAll(PRECACHE_ASSETS);
    })
  );
  self.skipWaiting();
});

// Activate event - clean old caches
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((cacheNames) => {
      return Promise.all(
        cacheNames
          .filter((name) => name !== CACHE_NAME)
          .map((name) => caches.delete(name))
      );
    })
  );
  self.clients.claim();
});

// Fetch event - network first, fallback to cache
self.addEventListener('fetch', (event) => {
  // Skip non-GET requests
  if (event.request.method !== 'GET') return;
  
  // Skip API requests - always go to network
  if (event.request.url.includes('/api/')) return;

  event.respondWith(
    fetch(event.request)
      .then((response) => {
        // Clone and cache successful responses
        if (response.ok) {
          const responseClone = response.clone();
          caches.open(CACHE_NAME).then((cache) => {
            cache.put(event.request, responseClone);
          });
        }
        return response;
      })
      .catch(() => {
        // Fallback to cache
        return caches.match(event.request);
      })
  );
});
```

### 2E: Register Service Worker

Create `components/ServiceWorkerRegistration.tsx`:

```typescript
"use client";

import { useEffect } from "react";

export default function ServiceWorkerRegistration() {
  useEffect(() => {
    if ("serviceWorker" in navigator) {
      navigator.serviceWorker
        .register("/sw.js")
        .then((registration) => {
          console.log("SW registered:", registration.scope);
        })
        .catch((error) => {
          console.log("SW registration failed:", error);
        });
    }
  }, []);

  return null;
}
```

Add `<ServiceWorkerRegistration />` inside the `<Providers>` wrapper in `layout.tsx`.
